# 2.2：审核准备与人工分诊

本版范围：真实 CLI 环境检查和独立连通测试、可复用审核团队、人工分诊后修复。

- 启动并行审核时检查待运行 CLI 的安装、版本和必要参数。环境检查不请求模型；登录状态仅作参考，模型权限和思考强度需通过真实连通测试确认。
- 连通测试由用户单独发起，使用空临时目录、独立会话和只读审核适配器，可能消耗额度。支持停止和超时，不读取目标项目。
- 审核团队模板保存在 Studio 数据目录，支持全局或当前项目、保存新模板、更新、删除与应用。保存公共要求、范围、并发、超时及审核员配置，不保存运行状态、凭据和会话。版本冲突拒绝覆盖。
- 发现默认待验证。人工可记录确认问题、采纳建议、待业务确认、误报或暂缓，并填写依据。仅确认的缺陷/风险和采纳的建议可修复；业务问题不直接进入修复。
- 分诊不是独立复核，也不表示缺陷已修复。分诊历史绑定原始证据，重试产生新证据后必须重新判断。旧报告无分诊时按待验证处理。
- 修复仍需源码指纹匹配、测试门禁和独立复核。自动执行复现命令、自动分诊及跨报告问题合并留待后续版本。

验收覆盖：缺失 CLI/参数与取消、真实调用结果不误报、模板隔离与冲突、分诊证据变更及修复门禁、已有工作流回归、浏览器保存应用与分诊交互。

## 使用步骤

1. 选定工作区和“并行审核”，配置各审核员，或选择模板后点击“应用模板”。保存新模板可选择项目或全局范围；更新已有模板保留其原有可见范围。
2. 点击“检查本机环境”。需要确认所选模型、强度及账户能否调用时，点击“测试模型连通（消耗额度）”。过程中可停止；失败信息不返回原始认证输出。
3. 启动审核。环境检查失败时不会启动任何审核员，报告显示原因。修改本机环境后可重试未完成审核员。
4. 在每条发现下选择分诊结论、填写判断依据，点击“保存分诊”。确认问题和采纳建议后才能勾选。部分报告仍需确认其不完整性。
5. 在左侧配置开发方、独立审查方与测试命令，然后点击“修复选中问题并独立复核”。人工分诊记录会随修复来源一起保存。

模板保存在 `.studio/audit-templates.json`；使用 `STUDIO_DATA_DIR` 时遵循该目录。分诊记录在审核 `state.json` 的 `triage` 字段中，旧审核报告无需迁移。环境检查报告随审核保存，独立连通测试结果仅在当前页面显示。

接口：`POST /api/agent-health`（`mode: check | probe`）、`GET/POST /api/audit-templates`、`POST /api/audit-templates/delete`、`POST /api/audits/:id/triage`。模板更新/删除须携带版本；分诊须携带发现 ID、原始证据标识和分诊版本，冲突返回 409。现有审核读取接口补充分诊状态和 `repairable` 标志。
