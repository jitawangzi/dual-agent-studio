# 并行审核页面交互验收

日期：2026-10-03。结论：本轮覆盖的页面流程通过，未发现阻断性功能问题；真实模型审核质量与 CLI 端到端调用不在本次结论内。

## 环境与测试边界

- 使用 Codex 内置浏览器自动化实际操作页面，没有通过修改页面状态伪造结果。
- 原服务 3700 在 Codex 重启后已退出，本轮重新启动并刷新页面。
- 3700 使用项目原有 Mock provider，验证从页面启动两个独立审核员到零发现报告的完整链路。
- 3701 是隔离验收实例，沿用原 server、前端、持久化、审核与修复工作流；只注入确定性测试 Agent。测试适配器在报告中明确注明其身份，不调用真实模型。
- 隔离实例仅允许 Mock provider 和 `.studio/ui-acceptance-20261003/project` 样例目录。修复时确实给样例函数增加空值保护；测试门禁确实执行 `node test.js`；独立测试复核器重新加载并执行该函数。
- 使用标准表单输入、下拉选择、键盘激活控件。原窄栏标签页上的自动化点击未改变 radio 状态，键盘选择成功；本轮不把该现象认定为产品代码缺陷，也不声称已完成所有鼠标及响应式布局验收。

## 已验证

| 项目 | 结果 |
| --- | --- |
| 切换并行审核模式 | 审核配置与报告可访问，启动入口随模式变化 |
| 模型与思考强度 | 已知模型显示支持的强度；手动输入未知模型后强度禁用并回到默认 |
| 审核员编辑 | 添加、移除审核员有效，个人提示词独立保存 |
| 原始 Mock 并行运行 | 两位审核员均完成，使用不同 sessionId，公共及个人要求正确持久化 |
| 部分失败 | 一位完成、一位失败时显示“部分完成”，保留已有报告与错误 |
| 部分结果修复门禁 | 选中缺陷后仍不能修复，须显式勾选接受部分报告；取消确认后再次禁用 |
| 待确认问题 | QUESTION 类别不可直接勾选修复 |
| 失败重试 | 仅失败审核员执行第二次；已完成审核员 attempt 保持 1，重试者为 2，沿用原 sessionId |
| 报告合并 | 两份各三项发现合并为三项，每项保留两个来源 |
| 人工选择修复 | 只勾选一个缺陷，修复账本只导入一项，未勾选的建议及问题未导入 |
| 修复与独立复核 | 测试 PASS，连续两轮复核通过，BUG-0001 为 VERIFIED_CLOSED，运行 APPROVED |
| 运行互斥 | 正在审核时启动按钮禁用，停止按钮可用 |
| 停止与排队取消 | 并发为 1 时，运行中及排队审核员均进入 STOPPED；排队者 attempt 为 0 |
| 刷新与历史 | 页面重载后配置、审核记录及关联修复入口保留，历史切换正常 |
| 审核证据入口 | 可展开并显示逐次提示词、原始回答和 state.json 链接 |
