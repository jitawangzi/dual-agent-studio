# 2.3：独立验证发现与分诊筛选

本版为审核与人工分诊之间增加独立验证阶段。验证辅助人判断，不自动采纳建议、确认误报、修复代码或关闭缺陷。

## 使用

1. 完成并行审核后，在报告内展开“独立验证审核发现”，为验证 Agent 选择引擎、模型、思考强度及补充要求。设置独立于审核团队和修复审查方。
2. 按关键词、类别、严重程度、分诊状态或验证结果筛选。改变筛选清空勾选，避免提交隐藏事项。也可以选择当前显示的前 20 项。
3. 勾选各发现的“选择验证”。每次最多 20 项，每项使用新的独立会话顺序验证。部分审核结果需要显式确认其不完整性。
4. 可选填写复现命令，并勾选执行确认。命令在当前目标工作区执行一次，其输出作为这一批发现的共同验证材料。验证 Agent 必须判断命令是否真正覆盖对应问题。
5. 未填写命令时，只读检查源码、检查原始证据、给出建议验证步骤。Agent 提出的新命令不会自动执行，可检查后填入命令框重新验证。更改命令或切换审核记录会清除执行确认；切换工作区还会清空命令，避免在另一项目误执行。
6. 查看每项验证结论、步骤、预期/实际结果、局限、命令退出码与输出。然后人工填写分诊依据；确认后才可勾选修复。

## 结论边界

| 结论 | 含义 |
|---|---|
| 已复现（Agent 判断） | Studio 确实执行了命令，Agent 判断输出支持该缺陷。保存输出引用，仍需人工判断结论正确性。 |
| 源码证据支持 | 静态证据支持发现，不代表运行复现。 |
| 本次未复现 | 执行了命令，但未观察到对应现象。不等于误报或已修复。 |
| 证据不足 | 检查或测试覆盖不足，不能作肯定判断。 |
| 待业务确认 | 需要补充接口契约或业务要求。 |

“已复现”和“本次未复现”要求存在真实结束的命令记录及可匹配的输出引用，只适用于缺陷和风险。非零退出码可能是环境问题，不能自动确认为缺陷；成功退出也不能自动否定发现。模型仍可能误判引用的意义，所以这不是机械证明。

命令由用户显式授权，使用工作区现有权限执行，可能有文件或外部副作用；不是隔离沙箱。源码指纹检测到变化时报告失效，需重新审核。验证 Agent 沿用只读适配器；不提供自动执行模型生成命令的路径。

## 状态与证据

- 验证与审核、讨论、修复、连通检查互斥。支持停止、超时及服务重启后的中断识别。重启不自动重放复现命令；重新验证生成新记录和新会话。
- 留存审核发现原文、来源、源码指纹、验证配置、命令/原始输出、提示词、原始回答和分诊历史。单段输出给模型最多 16,000 字符，完整 stdout/stderr 在日志中查看。
- 新验证记录会让先前分诊失效，需重新查看后确认。修复记录保存准确分诊版本和独立验证证据；之后仍要通过测试和修复后的独立复核。
- 启动验证、修复及验证执行前后会检查源码指纹；不通过页面轮询持续扫描源码。检测到源码或原审核证据变化后，旧验证只作历史参考。失败、取消和格式不合格不会伪装成有效验证结论。
- 旧报告无需迁移。验证配置保存在浏览器草稿中；团队模板仍保存审核团队配置。复现命令与执行确认不跨页面重载自动恢复。

## 接口

`POST /api/audits/:id/verify`：`workspaceRoot`、`findings: [{id,evidenceKey}]`、`verifier`、`timeoutSeconds`，可选 `reproductionCommand`、`executeReproduction`、`acceptPartial`。返回 202 及 `verificationId`。

审核 `state.json` 增加 `verificationRuns`；读取审核接口的每项发现增加 `verification`、`verificationHistory`、`verificationKey`。分诊提交携带当前 `verificationKey`，旧页面冲突返回 409。`GET /api/status` 增加 `activeVerificationId`；继续使用 `/api/stop` 停止。
