# 2.7 审核证据与覆盖范围

本版为并行审核、修复复查和方案逐项验收增加结构化证据及覆盖范围，不改变人工分诊、批准方案和独立复核的职责。

## 页面使用

- 并行审核结果中，每位审核员分别展示检查对象、已检查 / 未检查 / 存在争议、检查内容与限制。可打开本次原始回答，查看完整上下文。
- 问题来源和修复台账中，源码依据展示文件、行号、解释及源码指纹。源码依据是 Agent 声明，系统没有自动确认文件内容或推理正确性。
- 逐项验收、Bug 复查中，测试依据展示退出码、原文片段及测试日志链接。测试证据只证明相应命令确实执行，不自动证明测试覆盖了这个需求。
- 各轮记录保留本轮测试输出、审核原始回答、开发前后源码指纹和开发后的 Git diff。Git diff 相对 HEAD，包含已有修改，不包含未跟踪文件；它不是本轮独立补丁。非 Git 工程或获取失败时明确记录不可用。

## 返回协议

报告新增可选 `coverageDetails`：

```json
[{"target":"src/auth.js","status":"UNCHECKED","checks":"缺少登录集成测试","limitations":"尚无测试账号"}]
```

状态为 `CHECKED`、`UNCHECKED`、`DISPUTED`。同一报告对象不得重复。只要含未检查或争议条目，`scopeComplete` 就不能为 true，否则报告校验失败。覆盖信息是每个 Agent 的自报清单，不是全项目覆盖百分比；未列出的模块仍未知。不同审核员的结论分别保留，不通过多数票合并成正确结论。

发现、复查和验收项新增可选 `evidenceRefs`：

```json
[
  {"kind":"SOURCE","file":"src/auth.js","startLine":12,"endLine":18,"explanation":"检查到空值分支"},
  {"kind":"TEST","artifact":"从 Latest test evidence 读取的准确文件名","quote":"日志中的原文片段","explanation":"说明片段和该验收项的关系"}
]
```

系统拒绝越界路径、不合法行号、没有 Studio 执行记录的 TEST 引用、不同源码版本、不同日志文件以及不存在于记录输出中的引用。并行只读审核没有 Studio 测试门禁，因此不能声明 TEST 引用；需要复现时使用已有独立验证功能。

测试门禁保存 `artifact`、`beforeSnapshot`、`snapshot`、退出码和 `truncated`。模型可引用的输出仍限制为末尾 16000 字符；完整输出保存在日志文件内。源码引用标注 `AGENT_SOURCE_CLAIM`，通过来源校验的测试引用标注 `STUDIO_EXECUTION`。不存在自动证明语义正确性的能力。

## 兼容与边界

- 旧报告、旧模型输出仍可读取；缺少新字段时页面显示“未提供结构化证据 / 覆盖范围”，不伪造执行证明。未强制旧模型输出新字段，原有验收门禁仍有效。
- 定向复查与整体回归均校验证据；虚假 TEST 引用使本次复查失败，不能据此关闭问题。
- 本版没有新增模型调用，没有自动执行 Agent 建议的命令，也没有自动合并代码。
- 2.6 尚未完成的浏览器交互验收和真实模型联调仍需补验；本版状态见 [验收记录](version-2.7-acceptance.md)。
