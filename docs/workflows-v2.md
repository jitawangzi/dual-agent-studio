# Dual-Agent Studio 2.1 工作流

## 并行审核（第一版）

1. 选择工作区，切换「并行审核」，在「审核报告」页填写公共审核要求。公共范围使用左侧「检查 / 实施范围」。仅审核时不需要测试命令。
2. 添加 1–8 位审核员，各自选择 Agent 引擎、模型预设或手动模型 ID、思考强度、个人提示词及补充范围。同一引擎可添加多次，分别使用不同模型或检查重点。
3. 并发数可选 1–4，默认 3；超时沿用左侧「每阶段超时」。第一版提供 Claude Code、Copilot、Codex CLI、Pi Coding Agent、Mock，其他引擎尚未进入此模式的只读适配列表。
4. 思考强度取当前模型字典与引擎适配器支持档位的交集。未知模型或未配置能力的模型只能使用 CLI 默认强度；可通过模型字典补全后刷新页面。实际模型可用性仍由登录账号及 CLI 决定；不支持的参数会报错，不会伪装成成功。
5. 各审核员独立会话、并行读取同一工作区。报告分为「缺陷」「实现隐患」「优化建议」「待确认问题」，每项附文件位置、证据和验收条件。相同类别、路径与规范化问题描述合并，所有原始来源保留；不同表述和分歧不会靠投票消除。
6. 「审核完成」仅代表所有审核员完成其范围检查，不是无 Bug 保证。单个失败、超时或未覆盖范围显示「部分完成」，保留其他报告；可以「重试未完成审核员」。停止和服务重启同样保留历史；旧进程仍存活时禁止重试和转修复。
7. 在结果中勾选缺陷、隐患或建议，确认左侧开发 Agent、复核 Agent、真实测试命令和轮次配置，再点击「修复选中问题并独立复核」。部分结果需勾选“我了解本次审核尚未完整完成”。待确认业务问题需先澄清，不能直接转修复。
8. 修复仅从服务端保存的勾选项建立 Bug 台账，保留来源审核与证据，自动提交关闭。后续由现有测试和独立复核闭环验收；「查看修复运行」可跳转记录。

只读限制由 CLI 工具限制及源码指纹共同实现：Copilot 限定 view/grep/glob，Claude 限定 Read/Glob/Grep 并排除其他 MCP 配置，Pi 限定读取工具。Codex 使用只读沙箱，单次调用禁用 app/plugin/browser 工具，并枚举、禁用配置中的 MCP；枚举或兼容性校验失败会停止该审核员。这些调用级设置不改写用户全局配置。Codex MCP 禁用参数参照 [官方配置说明](https://developers.openai.com/codex/config-reference)。审核不会由编排器运行可写测试命令；需要执行验证的不足应写入报告。

源码发生变化会使审核失效；转修复前也会重新比较指纹。此约束防止用旧报告直接修改新代码，不是对外部 CLI 或用户安装扩展的系统级隔离。审核期间不要同时手动编辑目标工程。

审核记录、各次提示词、原始回答和日志保存在 Studio 的 `.studio/audits/`，不会写入目标项目。配置保存在当前浏览器本地，历史按工作区查询。

新增接口：`GET /api/audit-capabilities`、`GET/POST /api/audits`、`GET /api/audits/:id`、`GET /api/audits/:id/artifacts`、`POST /api/audits/:id/retry`、`POST /api/audits/:id/repair`。修复请求包含 `findingIds` 和现有修复配置；部分审核还需 `acceptPartial: true`。全局停止仍使用 `POST /api/stop`。

## 方案讨论与人工批准

1. 选择项目和两个 Agent，切换「需求讨论」，描述想改善什么，不必先知道实现方案。
2. Agent 只读调查工程，给出代码证据、备选方案（含最小改动方案）、成本、范围、待决策问题和验收条件。
3. 在「补充需求 / 方案取舍」填写意见，点击「带着我的意见继续讨论」，可多次产生新版本。
4. 编辑最终方案后，选择「仅批准并保存版本」或「确认共识方案并开始执行」。技术共识与人工批准分别记录；有分歧时也允许人明确取舍。
5. 后端保留原草案、准确的批准文本、版本、内容摘要和批准时间。执行绑定此版本，修改请求中的任务文本会被拒绝。
6. 开发方或审查方报告范围变化时进入 `NEEDS_ATTENTION`。讨论并批准新版后，在原运行填写人工决策继续，保留 Bug 台账。

## 工程审查与修复

1. 切换「审查修复」，填写范围和真实测试命令。任务描述可留空，也可指定重点模块。
2. 先测试、审查已有源码，即使没有 Git Diff 也可开始。没有发现问题时，不调用修复 Agent。
3. Bug 保存稳定 ID、位置、严重度、证据、验收条件与历史。修复方只能提交修改；独立审查方提供具体证据后才能关闭问题。
4. 漏报旧 Bug 不会将其关闭；同一问题可重新打开。争议进入人工决策，补充依据后继续复核，人工备注本身不会直接关闭 Bug。
5. 完成要求：约定范围检查完成、方案模式的验收标准完成、所有确认问题复核关闭、测试通过，且达到连续无新增问题轮数（默认 2）。源码改变会重置连续计数。
6. CLI 失败、格式错误、测试失败、审查期间源码改变、轮数用尽均不会误报通过。轮数用尽后可人工确认追加轮数。

“无新增问题”表示本次约定范围与检查方法下未发现问题，不是对整个工程绝对无 Bug 的证明。

## 运行记录与恢复

- 「运行记录」按项目列出任务，显示阶段、Bug 台账、各轮结果；「运行证据与原始记录」包含提示词、原始回答、测试输出和事件日志。
- 状态写在 Studio 自身的 `.studio/`，可用 `STUDIO_DATA_DIR` 指向其他目录。不要指向目标工程的源码目录。
- 新版讨论不覆盖目标项目的 `IMPLEMENTATION_PLAN.md`。旧讨论文件仍可读取；新版批准需要重新讨论生成版本记录。
- 停止、异常、服务重启后的任务可恢复。恢复先测试、审查现有代码，不盲目重放中断的修改。旧进程仍存活时拒绝恢复，以免两个进程同时修改。
- 一次只运行一个讨论或执行任务。每次执行生成独立的开发、审查会话 ID，同一运行的后续轮次和恢复复用这些 ID。界面历史会话输入用于需求讨论。
- 自动提交默认关闭；开启时要求起始 Git 工作区干净。提交失败会记录错误。当前直接在选定目录执行，不自动创建 worktree；同时手动编辑可能导致快照校验失败。
- Git 源码快照覆盖跟踪文件及非忽略的新文件；非 Git 工程排除依赖、构建输出和 Studio 数据。含 submodule 时需对子模块分别运行。快照用于变更检测，不是系统沙箱。
- 测试命令必须执行真实检查，空命令或单独的 `exit 0` 会被拒绝。测试覆盖范围仍取决于你配置的命令。

## Agent 适配

讨论、开发、审查共用 `engine/provider-adapters.ps1`，统一标准输入或临时文件传参、超时和退出码检查。CLI 不存在时直接失败，不再输出“已派发”的占位成功结果。

- Claude、Copilot、Codex、Pi 接入原生会话机制。Aider、Antigravity、Cursor 当前用每轮完整任务、Bug 清单和报告传递上下文，未接入其原生会话恢复。
- 只读阶段使用 CLI 支持的只读工具或模式，并检查源码指纹。编排器独立运行测试，再把测试证据交给审查方。
- 自动测试使用 Mock 和注入的多轮/失败场景，不调用收费模型。部分 CLI 参数已核对本机帮助；真实账号、模型可用性及 CLI 版本差异仍需实际环境联调。
- Mock 只用于验证工具流程，Mock 的 `APPROVED` 不是对工程质量的审查结论。

## 接口与模块

| 接口 | 作用 |
| --- | --- |
| POST /api/discuss | 讨论；可传 parentPlanId、humanFeedback 修订旧方案 |
| GET /api/discuss?workspace=... | 最新讨论及 planId、planVersion |
| GET /api/plans?workspace=... | 方案记录 |
| POST /api/plans/:id/approve | workspaceRoot、version、text；保存人工批准 |
| POST /api/runs | direct / plan / audit 运行；plan 需 planId、approvalId |
| GET /api/runs?workspace=... | 运行历史 |
| GET /api/runs/:id | 状态和 Bug 台账 |
| GET /api/runs/:id/artifacts | 证据文件列表；name 参数读取文件 |
| POST /api/runs/:id/resume | 恢复停止、失败、中断的任务 |
| POST /api/runs/:id/decision | note、extraRounds；plan 还需已批准的 planId、approvalId |
| POST /api/stop | 停止当前执行或讨论 |

- `engine/workflow.js`：阶段、Bug 台账、完成条件。
- `engine/run-store.js`：原子状态、事件和批准记录。
- `engine/process-runner.js`：进程、输出、取消、超时。
- `engine/agent-bridge.ps1`：Node 请求与公共 Provider 层桥接。

旧 `/api/start` 与 `engine/orchestrator.ps1` 使用原 Mailbox 协议，保持兼容；新版批准、台账、快照验收与恢复约束只适用于 `/api/runs`，新版网页全部走此接口。
