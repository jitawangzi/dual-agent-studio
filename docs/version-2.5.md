# 2.5：团队讨论与人工决策

## 使用流程

1. 选择工程，在“需求讨论”模式输入初步想法和范围。
2. 打开需求讨论区，配置 2–6 位成员。每位可指定角色名称、Agent 引擎、模型、思考强度和角色提示词；配置独立于左侧开发/审核 Agent。模型预设来自本地字典，未知模型仅使用默认强度，实际可用性由 CLI 判断。
3. 启动讨论。第一位先调查真实工程文件；每位随后独立提出 1–3 项改动，再交叉评价所有其他成员的提案。最多 3 位并发。每次调用使用独立会话，保留输入、原始回答和进度，不以多数票自动通过方案。
4. 查看源码观察、约束、收益、风险和质询。对每项提案选择采纳或暂缓并填写理由；至少采纳一项。采纳项可以增删或修改验收条件与验证方法。所有业务问题都要答复。
5. 生成完整预览，核对后批准。改变任何取舍、验收条件或答复都会使预览失效。批准不启动开发；点击“按已批准方案开始实施”后才使用左侧开发/审核 Agent 和测试门禁。
6. 在轮次页查看每项 `A-…` 验收条件的独立复核结果和证据。条件不通过会继续修复；业务含义无法判断则请求人工决策。需要修改方案时填写补充意见创建下一版讨论，批准后在运行的“本次继续使用的已批准方案”中明确选择新版本。

## 完成标准与中断

- 所有成员的提案和交叉质询都完成，讨论才进入人工取舍。单个 Agent 失败不会把部分结果当完整方案；可查看已保存回答，补充意见后重新调查讨论。
- 调查至少引用一个工程内真实文件，拒绝不存在文件、越界路径和指向工程外的链接。文件存在检查不证明 Agent 的分析正确，仍需结合原始回答判断。
- 调查开始建立源码指纹；每次调用前后、最终讨论完成及批准时检查。审批后、首次实施前还会检查，源码变化则阻止沿用旧方案。指纹沿用现有规则：Git 跟踪及未忽略文件；非 Git 工程排除常见依赖/生成目录。
- 审批保存精确方案、人工取舍、答复和结构化验收条件。实施审查不能只给一个 `acceptanceComplete: true`；必须逐项返回唯一 ID、PASS / FAIL / BLOCKED 和证据。缺项、重复、未知 ID 或自相矛盾均失败。
- 测试门禁仍只执行用户设置的命令，方案中模型建议的验证方法不会被 Studio 自动作为命令执行。
- 停止会等待调用结束；服务重启将未完成讨论标记中断，保留进程记录，不自动重放。仍存在旧进程时同工作区禁止启动新讨论。
- Mock 只演示流程；结构化验收返回 BLOCKED，不能冒充真实代码验收完成。真实模型的判断质量未由 Mock 测试验证。

## 当前边界

这一版每次讨论包含一次调查、一次独立提案、一次交叉质询；进一步迭代通过“带着意见创建下一版讨论”，不是模型无限自动辩论。第一次调查由首位成员完成，各成员仍可独立读取源码。不会自动合并不同表述的提案或消除互斥方案，人工负责取舍。

团队配置保存在当前浏览器。批准前的取舍草稿在当前页面内保留，轮询和切换记录不会清空，但刷新整个页面会丢失未批准输入。已完成讨论和已批准方案均落盘，可刷新恢复；不包含团队模板、草稿跨设备同步、成本统计或模型输出格式自动重试。

只读能力沿用审核适配器的工具限制和源码指纹检测，不能替代操作系统级隔离。使用本地受信任工程和已配置的 CLI；无需新增 npm 运行时依赖。

## API 与兼容

- `POST /api/planning`：传 `workspaceRoot, idea, feature, scope, members, timeoutSeconds`；可带 `parentId, feedback` 创建下一版。
- `GET /api/planning?workspace=…` 与 `GET /api/planning/:id`：历史及当前状态。
- `POST /api/planning/:id/preview`：传 `workspaceRoot, version, selections, answers`，返回精确方案、条件和 `previewHash`。
- `POST /api/planning/:id/approve`：同上加 `previewHash`，检查源码后批准并返回可交给 `/api/runs` 的方案及审批 ID。
- `GET /api/planning/:id/artifacts`：调用证据文件列表，可用 `name` 读取原始文本。
- `/api/status` 增加 `activePlanningId`，`/api/stop` 覆盖团队讨论。
- 旧 `/api/discuss` 与双 Agent 历史仍保留，旧版入口收纳在折叠区；与新版结构化讨论记录分开。旧计划兼容原有审批和运行方式。

记录位于 `.studio/discussions/<id>`，批准结果位于 `.studio/plans/<id>`，不在目标工程写入讨论文件。
