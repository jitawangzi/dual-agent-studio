# 并行审核第一版

用户已批准：只读并行审核 → 汇总报告 → 人工勾选问题 → 现有修复与复核闭环。

- 不增加运行时依赖，Windows PowerShell 7 / Node.js 18+。
- 每位审核员独立配置引擎、模型、思考强度、提示词和范围，共享公共提示词。1–8 名审核员，1–4 并发，默认 3。
- 仅开放已有只读工具限制的 Claude、Copilot、Codex、Pi 与 Mock。按引擎适配参数和模型字典交集提供思考强度；未知模型允许手填 ID，但只支持默认强度。启动前校验，不静默忽略参数。实际账号/模型能力仍由 CLI 校验。
- 独立会话、独立进程和原始证据；同一源码指纹。源码变化使报告失效，不允许把失效报告转为修复。
- 结构化报告区分 BUG / RISK / SUGGESTION / QUESTION，必须给出证据、验收条件和实际检查覆盖。相同类别、路径与问题描述规范化后合并，保留所有来源；不同意见保留原报告，不以投票作结论。
- 完成指审核过程完成，不代表没有 Bug。任何审核员失败或范围未覆盖则为 PARTIAL；全失败为 FAILED；停止保留已有结果。重启标记 INTERRUPTED；重试只跑未成功审核员且要求源码未改变。
- 新审核记录保存在 .studio/audits，完整结果与原始文件可查看。整个 Studio 同时只运行一个顶层任务，单个审核任务内部并发。
- 人工选择 BUG/RISK/SUGGESTION，QUESTION 不可直接修复。只有服务端保存的 finding ID 可转为任务，绑定原工作区、源码指纹和证据。部分审核须显式承认未完成。新任务只修复已选问题，写入 Bug 台账，使用原有测试/复核闭环；不自动提交。
- 界面新增「并行审核」模式和「审核报告」页。保留审核配置、历史、各审核员进度、来源、完整报告、失败和证据，提交修复前说明使用下方开发/复核/测试配置。

验证：真实调度器搭配可控外部 Agent 回答，验证并发上限、独立会话、逐 Agent 参数、部分失败、取消、快照变化、重试、选择转修复与台账复核；HTTP Mock PowerShell 集成；页面交互；完整 npm test。
