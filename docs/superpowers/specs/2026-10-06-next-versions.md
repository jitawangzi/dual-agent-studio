# 2.10–2.14 后续版本设计与范围

状态：**规划文档，尚未实现**。基线 2.9.0；用户要求将后续优化及交接准备好，交由其他模型逐版实施。本轮不改业务代码。执行者默认单 Agent，按用户指定版本开工。

## 项目级约束

- Windows / PowerShell 7 / Node.js 18+；已测 Node 22.22.1 不等于已覆盖全部版本。
- 后端零新增 npm 运行时依赖，沿用 Node 内置库与原生 JS/CSS。
- 默认一个全局工作流，保留审核内部并发；不以本路线图引入多项目并发执行。
- 开发与审核会话独立，审核只读，不能以 Agent 自述或多数票替代证据。
- 人工批准绑定精确版本；证据改变后必须重新确认。暂停、失败、额度不足都不是通过。
- 测试与模型探测仅按用户明确配置执行；调用次数、额度和价格未知时显示未知。
- 旧记录和原报告必须保留；迁移有备份，不能清空用户数据。
- 先完成指定任务及验证，再扩展下一项；不自动提交、推送或调用真实付费模型。

## 优先级与依赖

```text
2.9 已完成
  └─ 2.10 数据/生命周期/可复现验收
       └─ 2.11 调用统计与硬预算
            └─ 2.12 变更分析与定向复查
                 └─ 2.13 争议与人工决策
                      └─ 2.14 导出、诊断与归档
```

后面版本可以拆独立任务，但合入顺序保持上述顺序，避免多模型同时修改 `server.js`、`run-store.js` 和工作流核心。

| 版本 | 用户价值 | 本版完成标准 | 明确不做 |
|---|---|---|---|
| 2.10 | 重启、旧数据、故障后仍可信 | 迁移/坏记录可诊断、跨入口互斥、残留进程保护、验收脚本入库 | 更换框架、数据库、多用户服务 |
| 2.11 | 控制 Agent 调用浪费 | 可见每步尝试/耗时/模型，启动前估计调用数量，硬限制调用与时间，配额错误暂停 | 承诺账户剩余额度、自动买额度、静默降级模型 |
| 2.12 | 小改动少读无关文件 | 明确变更清单、人工确认定向计划、所有缺口/旧问题可追踪，范围外修改失效 | 自动依赖图完备性、默认沿用旧通过结论 |
| 2.13 | 争议能留痕并由人处理 | 关联冲突、可选单次仲裁、结构化人工选择/暂缓/重新验证 | 多数票自动裁决、无限辩论、自动批准 |
| 2.14 | 证据可导出、迁机、排障 | 可校验脱敏导出、只读查看、按整组归档及恢复、诊断包 | 自动删记录、自动上传云盘/发消息、直接执行导入审批 |

## 重要设计取舍

**调用预算优先于账单估算。** 各 CLI 未必返回 token 和费用，订阅剩余额度也不能靠本地计数推算。第一版限制尝试次数、执行时间、并发；有 Provider 官方机器可读数据时再保存实际值，未知用 null。

**先定向审核，再考虑安全复用。** 2.12 可以缩小送给 Agent 的范围和人工明确的补查项，但人工总体验收仍按完整源码和范围门槛执行。禁止为节省额度把未检查区域默认为通过。

**争议是业务实体，不只是聊天记录。** 同一代码位置可能存在不同设计约束。先显式关联证据和问题，再由人决定是否补充验证、接受例外、重做需求；可选仲裁也只是新证据。

**导入数据不带执行权。** 迁机后的历史审批不是新机器的启动授权。导入只读报告不自动启动 Agent、执行测试或恢复任务。

## 暂缓到后续大版本

- 多工程并发、持久任务队列和定时自动审核：需要工作区写锁、成本限额与恢复语义先成熟。
- GitHub PR 评论、自动推送、自动合并：需要明确外部写入授权与认证设计；不在本计划里顺手加入。
- OS 沙箱、远程 Worker、多人权限：独立架构评审后做，不把现有只读 CLI 参数包装成安全沙箱。
- 自动选择最佳模型、模型竞技排名：需要真实质量数据，不能用 Mock 结果或者调用价格推导质量。

## 对执行模型的完成约定

每个任务都包含测试循环；版本验收须覆盖本版新行为与既有核心不变量。不得因为缺少某个 AI 技能或浏览器工具而跳过代码工作：可以用本计划的步骤手动执行；未做的验收明确记录。详细文件/API 设计是实施草案，开始任务时与真实代码核对；小范围命名调整写进 WORK_LOG，语义变更需用户决定。
