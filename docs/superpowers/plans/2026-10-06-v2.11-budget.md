# 2.11 调用预算与资源使用 Implementation Plan

> **For agentic workers:** 按任务逐项完成；可用 executing-plans，也可单 Agent 手动执行。默认不委派，不进行真实付费调用。

**Goal:** 让用户看清一次工作流调用了多少 Agent，并能在额度浪费之前按次数和时间暂停。

**Architecture:** 在各工作流调用 Agent 的统一边界记录尝试，持久化预算预留和消耗；启动估算不调用模型。暂停使用明确原因，不吞掉失败、覆盖已完成成果或静默更换模型。

**Tech Stack:** 现有 Node/PowerShell/原生前端，不新增运行时依赖。

**Spec:** [总体设计](../specs/2026-10-06-next-versions.md)。前置：2.10 数据版本和运行租约。

## Global Constraints

Windows / PowerShell 7 / Node.js 18+；零新增 npm 运行时依赖；全局单工作流；停止与预算耗尽不等于完成；未知 token/费用/剩余额度使用 null；不自动降级模型、充值或无限重试。

## Task 1：统一调用记录与真实/未知数据区分

**Files:** 新建 `engine/call-ledger.js`、`tests/call-ledger.tests.js`；修改 `workflow.js` 的 call、`audit-workflow.js` 的 review、`planning-workflow.js` 的 call、`finding-verification.js`、`agent-health.js` 的真实 probe。

**Interfaces:**

```js
beginAttempt(record, {stepId,role,provider,model,reasoningEffort,sessionId,startedAt}); // -> attemptId
finishAttempt(record, attemptId, {status,finishedAt,errorCode,usage});
summarizeCalls(record); // {attempts,completed,failed,interrupted,durationMs,usage}
// usage: {inputTokens:null|number,outputTokens:null|number,cost:null|number,
//         currency:null|string,source:'PROVIDER'|'UNKNOWN'}
```

每次真正尝试调用只生成一个 attemptId；同一步重试是新 attempt，同一次回调重复完成不能双计数。记录元信息而非复制完整 prompt。旧记录字段使用缺省值，不把旧日志无法确认的计数补成实际费用。

持久化映射固定为 execution kind `run→runs`、`audit→audits`、`planning→discussions`、`health→health`。最后一种为本版新增RunStore kind，应同时扩展storage-schema与旧数据兼容测试；只保存显式真实probe的元信息，不保存凭据。审核中的独立验证保存在同一audit预算下，通过 `{phase:'verification',childId:verificationId}` 标识步骤，恢复不能误跑审核员列表。

- [ ] 写重复回调、失败调用、输出格式错误、停止、服务重启测试；格式错误也是已消耗的尝试，不能从统计删除。
- [ ] 把生命周期写盘点放在进入 Provider 前、得到输出后、解析失败后。可区分 `CALL_FAILED` 和 `INVALID_RESPONSE`，并保留现有原始回答附件。
- [ ] 无可靠 usage 时 `cost:null`，不从回答字数推算美元；机器可读 usage 仅通过明确适配器解析，不从自然语言总结中提取。
- [ ] 各工作流保持原有会话隔离与业务状态；Mock 标注 provider=mock，不算真实账单。
- [ ] 执行 `node --test tests/call-ledger.tests.js` 并运行受影响的 workflow/audit/planning 测试。

测试示例：

```js
const r={};
const id=beginAttempt(r,{stepId:'review:1',role:'review',provider:'mock',startedAt:'2026-10-06T00:00:00Z'});
finishAttempt(r,id,{status:'INVALID_RESPONSE',finishedAt:'2026-10-06T00:00:02Z',errorCode:'INVALID_JSON'});
finishAttempt(r,id,{status:'INVALID_RESPONSE',finishedAt:'2026-10-06T00:00:02Z'});
assert.equal(summarizeCalls(r).attempts,1);
assert.equal(summarizeCalls(r).usage.cost,null);
```

## Task 2：并发安全的次数与时间硬预算

**Files:** 新建 `engine/execution-budget.js`、`tests/execution-budget.tests.js`；修改调用入口、记录恢复、暂停状态展示。

**Interfaces:**

```js
normalizeBudget(input); // {maxAttempts:null|integer,maxActiveSeconds:null|integer}
reserveAttempt(record, {stepId,nowMs}); // 同步预留；返回 reservationId 或抛 BUDGET_EXHAUSTED
markAttemptStarted(record, reservationId); // 不重复消耗
settleAttempt(record, reservationId, outcome); // 结算预留；失败/格式错也计入尝试
remainingBudget(record, nowMs); // used/reserved/remaining 与原因
```

校验范围：maxAttempts 为null或1–10000整数；maxActiveSeconds 为null或1–86400整数；拒绝字符串数字、NaN、负数和未知字段。预算调整的reason必须为1–10000字符。未传字段按null，不能把0解释成无限。

预算作用于当前工作流记录及其重试/恢复，不跨所有项目扣全局次数；新建关联补审是新记录，启动预览明确它会开启独立预算。自动下游步骤仍在当前记录预算内，不能通过内部重试重置 used。

- [ ] 写并发测试：上限1，两个审核员竞争，只允许1次 Provider 调用；`used + reserved` 不越界。
- [ ] 预留必须同步写盘后才调用外部进程。进程已开始或启动是否成功不确定时消耗1次；确定尚未尝试且取消的预留可释放，记录原因。
- [ ] 所有尝试（含失败/格式不合法）计入上限；本地 CLI 安装检查不计 Agent 尝试，真实连通 probe 计入它自己的明确预算。
- [ ] activeSeconds 按运行时长累计，暂停期间不累积，恢复不能重置。超时中止本记录所有在途调用并等待退出，保留部分有效成果。
- [ ] 活动时长定期checkpoint；崩溃导致未结算区间无法确认时设置 `uncertainActiveTime:true` 并等待人工恢复，不自动按0秒重置。界面区分实际可确认时间与未知区间。
- [ ] 预算耗尽使用 `pauseReason: BUDGET_EXHAUSTED`，带 allowedActions；不能伪装成审核 COMPLETED 或 APPROVED。各工作流状态枚举和 UI 标签一起更新。
- [ ] 服务重启遇到已开始但未结算尝试时标记 INTERRUPTED，保留消耗；不自动补跑。
- [ ] 通过已有生命周期租约停止和恢复，不引入第二套孤儿进程处理。
- [ ] 执行预算测试、并发审核测试、讨论局部重试测试和停止恢复测试。

## Task 3：额度错误分类与人工恢复

**Files:** 修改 `engine/agent-health.js`，抽出 `engine/provider-errors.js`；新增 `tests/provider-errors.tests.js`；修改 server 对应 workflow 控制端点。

**Interfaces:** `classifyProviderError(error) -> {code,retryable,retryAfterSeconds:null|number}`。固定 code：`AUTH_REQUIRED`、`MODEL_UNAVAILABLE`、`RATE_LIMIT`、`QUOTA_EXHAUSTED`、`TIMEOUT`、`UNKNOWN`。无法区分配额和限速时保守 UNKNOWN/暂停，不编造恢复时间。

- [ ] 使用去标识错误样本测试，涵盖命中/不命中；普通代码里出现“quota”不能让成功回答被分类为额度错误。只处理外部失败信号。
- [ ] QUOTA/AUTH/MODEL 直接暂停；RATE_LIMIT 第一版也交用户手动重试，不自动开启退避循环。TIMEOUT 可显示可重试，但不自行重复收费。
- [ ] 增加预算调整动作 `POST /api/executions/:kind/:id/budget`，kind=run/audit/planning/health；请求带 `workspaceRoot,version,budget,reason`，只允许空闲/暂停记录，追加修改历史。
- [ ] 增加 `POST /api/executions/:kind/:id/resume-budget`，携带版本，只恢复未完成步骤并重新校验源码；不能用它恢复业务争议、篡改既有人工批准或绕过旧进程。
- [ ] 验证未知 kind、旧版本、降低到 used 以下、未授权 workspace、活动任务调整都拒绝；提高额度本身不自动启动调用。
- [ ] 不允许静默修改 model/effort。换模型须生成显式的新尝试配置与来源记录，第一版可要求用户新建审核/讨论。

## Task 4：启动估算、预算 UI 和验收

**Files:** 新建 `engine/execution-estimate.js`、`public/execution-budget.js`；修改 index/app/audit/planning UI；新增对应 unit/API/UI 测试。

**Interfaces:** `estimateExecution(kind,config) -> {minimumAttempts,maximumAttempts:null|number,assumptions:string[]}`。只估调用次数，明确自愈、重试和额外轮次会增加；无法可靠得出上限返回 null，不能伪造精确费用。

- [ ] 启动区增加可选 maxAttempts/maxActiveSeconds；旧配置默认不限，与现有行为兼容。提供手动选择的“有限预算”预设，不强制改变已保存团队。
- [ ] 预览列出计划步骤、人数/并发、可确定的调用范围及未知因素；估算接口不得 spawn CLI 或调用模型。
- [ ] 运行页展示实际尝试列表、耗时、错误码、已用/预留/剩余预算。费用未知显示“未提供”，不能显示0元。
- [ ] 暂停页显示停止原因及提高预算、保持暂停、手动恢复入口；操作绑定版本，期间其他页调整返回409。
- [ ] 浏览器测试上限1的2审核员任务、预算耗尽后只重试未完成者、刷新保留计数、源码变更拒绝恢复、未知费用显示。
- [ ] 全量 npm test，记录独立浏览器结果，更新2.11版本与说明。

**版本退出条件:** 并发和恢复不能绕过硬预算；额度类错误不无限重试；已完成报告保留；用户能看清真实尝试与未知费用。精确账户剩余额度不作为本版完成条件。
