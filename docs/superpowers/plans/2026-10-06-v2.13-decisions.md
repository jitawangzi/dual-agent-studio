# 2.13 争议处理与人工决策 Implementation Plan

> **For agentic workers:** 按复选框逐任务实施，默认单 Agent。不要用多数票或再问一个模型代替人工决定。

**Goal:** 把审核冲突、实现约束和业务疑问变成可追溯的决策事项，并清楚区分“已经作出决定”和“已经完成修复验证”。

**Architecture:** 新增独立决策事项，引用已有证据而不复制/覆盖原报告；可选一次只读仲裁产生建议，最终由人选择后续动作。第一版每个事项只有一个可应用的分诊目标，其他关联内容只作证据。

**Tech Stack:** RunStore/Node内置库、现有只读Provider适配器、原生前端；无运行时依赖增加。

**Spec:** [总体设计](../specs/2026-10-06-next-versions.md)。依赖2.10存储/生命周期、2.11预算、2.12范围说明。

## Global Constraints

Windows / PowerShell 7 / Node.js 18+；人工决定绑定精确证据版本；仲裁不自动改代码、关闭Bug或批准验收；暂缓保留原因；所有模型尝试受预算管理；失败/证据变化不能变成已解决。

## Task 1：决策事项与证据引用

**Files:** 新建 `engine/decision-cases.js`、`tests/decision-cases.tests.js`；扩展 run-store/storage-schema 的 `decision-cases` kind；新增 schema fixture。

**Interfaces:**

```js
createCase(store,{workspaceRoot,title,question,anchor,references});
// anchor: null | {auditId,findingId,evidenceKey,triageVersion,verificationKey}
// references: [{kind:'AUDIT_FINDING'|'AUDIT_COVERAGE'|'RUN_BUG'|'PLAN_QUESTION',recordId,itemId}]
presentCase(store,id); // 解析服务器证据；返回 version、stale、状态、原来源链接
```

状态为 `OPEN / ANALYZING / AWAITING_HUMAN / DECIDED / NEEDS_REVIEW`；每次人工决定存为追加事件，旧决定不覆盖。

- [x] 创建测试：跨workspace引用拒绝、未知项拒绝、同项重复引用去重或拒绝、空业务问题拒绝；不能传客户端伪造证据正文。
- [x] 保存创建时解析的证据摘要/hash与引用；显示当前证据变化时标记 NEEDS_REVIEW，保留原快照作历史。
- [x] 同一文件并不自动等于同一争议。第一版由用户勾选关联，不用大模型自动合并相近描述。
- [x] 无anchor的业务事项可以讨论和决定，但不能直接改发现分诊；UI显示其后续动作是重做需求/新讨论。
- [x] 新kind加入路径白名单、迁移和导出预留；旧版本遇到新记录不能误写。
- [x] 执行 `node --test tests/decision-cases.tests.js tests/storage-compatibility.tests.js`。

## Task 2：可选单次仲裁与证据结构

**Files:** 新建 `engine/decision-analysis.js`、`tests/decision-analysis.tests.js`；复用audit-config、Provider桥接、预算与运行租约。

**Interfaces:** `analyzeCase(id,{workspaceRoot,version,reviewer,budget})`；reviewer使用既有provider/model/reasoningEffort/prompt结构。

仲裁回答格式：

```json
{
  "summary":"为什么存在分歧",
  "positions":[{"referenceIndex":0,"claim":"现有观点","support":"具体证据","limitations":"适用边界"}],
  "options":[{"id":"O-1","action":"VERIFY_MORE","reason":"缺少复现环境","risks":"仍无法排除缺陷"}],
  "questions":[{"id":"Q-1","text":"业务是否允许空输入"}]
}
```

- [x] referenceIndex只能引用本次给定证据；未知/重复option ID、缺解释、建议直接关闭Bug的未定义action均拒绝。
- [x] 允许action固定为 VERIFY_MORE/REPLAN/CONFIRM/ACCEPT_SUGGESTION/DEFER/DISMISS；这些是建议，不自动写triage。
- [x] 调用前后检查源码和证据版本；其中任何改变则建议保留原文但标记失效。
- [x] 限一次显式调用；继续分析要用户再次发起并消耗预算，不出现Agent互相无限追问。
- [x] 测试格式错误、额度耗尽、停止、重启、证据过期，均不能把事项标成已决策。

## Task 3：人工决定、应用分诊与幂等恢复

**Files:** 扩展 decision-cases；修改 audit-triage 以保存服务端来源标记；新增 `tests/decision-application.tests.js`；增加API。

**Endpoints:**

模块方法固定为 `decideCase(store,id,input)` 与 `applyDecision(store,{caseId,decisionId,version,workspaceRoot})`；applicationId由服务器生成并保存在case中，同一decisionId重试沿用原applicationId。

- `POST /api/decision-cases` 创建，`GET /api/decision-cases/:id` 查看。
- `POST /api/decision-cases/:id/analyze` 单次仲裁。
- `POST /api/decision-cases/:id/decide {workspaceRoot,version,action,note,answers}` 保存人工决定。
- `POST /api/decision-cases/:id/apply {workspaceRoot,decisionId,version}` 显式应用到anchor，不执行模型/命令。

- [x] decide要求当前证据版本、非空理由、业务问答完整；新决定只追加历史。旧标签页返回409，不替换其输入。
- [x] CONFIRM只能作用BUG/RISK并映射CONFIRMED；ACCEPT_SUGGESTION只能作用SUGGESTION并映射ACCEPTED。DEFER/DISMISS映射现有合法分诊，不等于修复关闭。
- [x] VERIFY_MORE/REPLAN仅记录决策及后续导航，用户在目标入口确认启动；不自动执行Agent建议的复现命令。
- [x] 应用采用可恢复的操作日志：先保存 `{applicationId,decisionId,status:'PENDING'}`；校验当前anchor版本；调用既有applyTriage；在分诊历史增加服务端 `decisionApplicationId`；最后标APPLIED。
- [x] 中途失败后重试先检查同applicationId是否已在triage历史；已写过则仅补齐APPLIED，不产生第二条分诊。若其他人先修改了anchor，标CONFLICT并要求新决定，不能强覆盖。
- [x] 未成功应用的事项显示“已决策，待应用”，不得让闭环忽略原待办。闭环只认成功写入的既有triage规则，测试/覆盖门槛不可被决定豁免。
- [x] 用注入写入失败覆盖上述三个边界，运行triage与closure现有回归。

示例关键测试：

```js
await applyDecision(store,input); // 成功写入一次
await applyDecision(store,input); // 网络重试
const history=store.read('audits',auditId).triage[findingId].history;
assert.equal(history.filter(x=>x.decisionApplicationId===applicationId).length,1);
assert.notEqual(store.read('runs',runId).status,'APPROVED'); // 决策不替代运行验收
```

## Task 4：争议工作台与验收

**Files:** 新建 `public/decisions.js`，修改index及audit/planning/closure导航，新增UI和HTTP测试。

- [x] 从审核发现、覆盖争议、问题台账和业务问答提供“创建决策事项”；创建前展示引用内容和目标，不默认把所有发现关联在一起。
- [x] 并排展示各观点的证据、局限和来源，不标“多数意见=正确”。仲裁区可配置模型/强度并展示预算。
- [x] 人工区包含选择、理由、业务答案；状态明确区分未决定、待应用、已应用、证据变化需重看。
- [x] 输入绑定证据版本，冲突时保留本地草稿；刷新恢复的最小方案沿用2.6模式，不复制一套不兼容规则。
- [x] 浏览器验证：两项冲突→创建事项→Mock仲裁→人工暂缓→应用一次→闭环显示原因；证据更新→旧决定不能应用。
- [x] 全量测试、截图、文档，真实仲裁模型质量未验证则明确说明。

**版本退出条件:** 人能解释并处理争议；应用结果可追踪且幂等；仲裁和人工例外都不能直接制造“Bug已验证关闭”或“测试通过”。
