# 2.12 变更分析与定向复查 Implementation Plan

> **For agentic workers:** 单 Agent 按任务推进；可用 executing-plans 辅助。只实施本版，不提前做自动依赖图或证据自动复用。

**Goal:** 为小改动生成可审阅的定向审核计划，减少无关上下文，同时清楚展示未覆盖区域。

**Architecture:** 在现有完整源码指纹旁保存可比较的文件清单；根据确定性的路径规则和原问题生成候选任务，用户确认后才启动定向审核。定向报告保留关联，但没有权限自行替代完整闭环基准。

**Tech Stack:** Node fs/crypto/path/child_process、Git 命令、既有 AuditWorkflow；无新运行时依赖。

**Spec:** [总体设计](../specs/2026-10-06-next-versions.md)。依赖2.10迁移与2.11调用预算。

## Global Constraints

Windows / PowerShell 7 / Node.js 18+；全局单工作流；旧源码指纹算法保持兼容；未检查不是通过；人工验收仍要求完整范围和当前逐项修复证据；测试/Agent调用受2.11预算控制。

## Task 1：可靠文件清单及变化分类

**Files:** 新建 `engine/source-manifest.js`、`tests/source-manifest.tests.js`；小范围修改 workflow 的 sourceSnapshot 实现以共享枚举逻辑，保留导出签名。

**Interfaces:**

```js
await buildManifest(workspace, {signal});
// {version:1,workspaceKey,snapshot,entries:[{path,kind,mode,sha256}],complete:true,exclusions:[]}
compareManifests(before,after);
// {added:[],modified:[],deleted:[],unchanged:[],renameCandidates:[],requiresFullAudit,reasons:[]}
```

- [ ] 写确定性测试：修改内容、同路径删除/新增、文件权限变化、未跟踪文件、符号链接、非Git工程、Windows大小写；变更列表不依赖操作系统目录枚举顺序。
- [ ] 共享现有 Git/非Git排除规则，保留 `.studio`/`.ai-workspace` 不进入源码。不能把被忽略文件的“没扫描”说成“内容相同”。
- [ ] 保持已有 sourceSnapshot 返回值的算法兼容；不能直接改成“文件哈希列表的哈希”，导致所有旧记录无故失效。
- [ ] 生成清单前后核对完整指纹；文件在扫描期间改变返回 SOURCE_CHANGED，不保存声称完整的混合快照。
- [ ] 超出文件数/读取边界、子模块不支持等情形明确失败或要求完整人工处理；不截断后仍 complete=true。
- [ ] rename 只作候选（相同内容的删增文件可能只是复制），不能自动移动原问题或继承通过结论。
- [ ] 测试“清单相同则差异为空”“只改变排除目录不污染现有指纹”，运行现有 sourceSnapshot 回归。

示例断言：

```js
const changes=compareManifests(before,after);
assert.deepEqual(changes.deleted,['src/old.js']);
assert.deepEqual(changes.added,['src/new.js']);
assert.equal(changes.renameCandidates.length,1);
assert.equal(changes.unchanged.includes('src/old.js'),false);
```

## Task 2：定向计划和保守扩大范围

**Files:** 新建 `engine/targeted-review-plan.js`、`tests/targeted-review-plan.tests.js`；修改 audit 的配置保存。

**Interfaces:**

```js
buildTargetedPlan({audit,manifestBefore,manifestAfter,findings,reviewers});
// {version,sourceSnapshot,baseAuditId,changedFiles,proposedTasks,uncoveredScopes,
//  requiresFullAudit,reasons,estimatedAttempts}
// proposedTasks: [{id,reviewerId,scope,checklist,sourceFindingIds,reason}]
```

- [ ] 按路径明确匹配审核员范围；无可解释匹配的文件放入“未分配”，不靠字符串相似度猜测架构归属。
- [ ] 将仍未关闭的问题及其验收条件列入复查候选；旧关闭证据过期的 Bug 也列入，不能只检查新 diff。
- [ ] 配置/锁文件/迁移文件、公共接口、删除文件、范围不明确、无基准manifest时，设置 requiresFullAudit=true 并列明原因。第一版规则列表是用户可见配置，不声称覆盖所有语言依赖。
- [ ] 将候选计划和确定性的输入摘要绑定 version；不调用模型生成“看起来精确”的依赖图。
- [ ] 预算预览复用2.11 estimateExecution，不因预览扣实际尝试。
- [ ] 单个 reviewer 超过20项时分成显式批次或提示缩小范围，不能静默丢项。每个批次及调用次数必须在批准计划中可见。
- [ ] 测试公共配置变化触发完整审核、删除文件仍关联旧问题、未匹配路径不消失、旧证据过期仍待验证。

交付：预览接口 `POST /api/audits/:id/targeted-preview {workspaceRoot}` 返回计划，无Agent调用、无执行授权。

## Task 3：批准定向范围并生成独立报告

**Files:** 修改 `engine/audit-workflow.js`、`engine/audit-closure.js`、`server.js`；新增 `tests/targeted-review-api.tests.js`。

**Endpoint:** `POST /api/audits/:id/targeted-start`，请求 `{workspaceRoot,version,taskIds,budget,note}`。服务端从已预览输入重新计算计划，不接受客户端自造“已完成检查”或源finding正文。

- [ ] 首先测试审批前源码变化、计划版本变化、未知taskId、空选项、重复选择、未处理requiresFullAudit都拒绝。
- [ ] 用户可选择只运行定向任务，但 requiresFullAudit 时必须返回“局部结果，完整审核仍待完成”的明确范围，不把定向结果标成整体通过。
- [ ] 创建新会话和新审核记录，保存 `targetedPlan` 和 `parentAudit.mode='TARGETED'`；不修改2.8补审的“同一源码”约束。
- [ ] 修改闭环的关联识别：TARGETED 不作为 RECHECK 基准，也不能通过现有补审递归路径偷换完整覆盖。旧记录缺mode时仍按2.8补审处理。
- [ ] 定向发现仍进入关联问题待办；只有明确的当前逐项验证能够关闭问题。定向未发现问题不能自动关闭原问题。
- [ ] 测试高风险场景：原审核A项已检查、B项未检查；源码变更后只定向补B，A必须仍显示过期，不得整体complete=true。
- [ ] 所有调用受当前预算、全局租约和停止保护；批准后源码再改变应失效，而不是自动切换基准。

## Task 4：变更预览与浏览器验收

**Files:** 新建 `public/targeted-review.js`；修改 index/audit UI；新增 UI/API测试和2.12文档。

- [ ] 页面展示新增/修改/删除文件、推荐审核员、每项理由、未覆盖范围、完整审核要求以及预算估算。
- [ ] 默认不选中未经确认的高风险例外。用户能切换到完整关联重新审核，沿用2.9入口。
- [ ] 定向运行后报告顶部持续显示局部范围，来源和人工选择说明可查看；不能仅在toast里提示一次后消失。
- [ ] 浏览器覆盖单文件变更、公共配置变更、选择部分任务、过期预览409、局部完成仍阻止整体验收。
- [ ] 全量npm test，更新版本/文档/WORK_LOG，记录实际减少的Mock调用或输入规模；不要宣称未经测量的真实费用节省比例。

**版本退出条件:** 缩小范围可解释、用户能批准、未覆盖区域始终显式、定向模式无法绕过完整闭环。自动复用未变文件的旧通过证据暂不实现。
