# 可直接复制给其他模型的提示词

建议每次只选一个版本或一个任务；无需安装本交接中提到的任何 AI 技能。没有子 Agent 的模型可以自行按检查表完成，不要因此停工。模型更换不代表允许更改方案、降低证据标准或重写整个工程。

## 首次接手：推荐从 2.10 开始

```text
你接手 D:\project\dual-agent-studio，当前工作区版本为 2.9.0。
先读 AGENTS.md、docs/handoff/README.md、CURRENT_STATE.md、ENGINEERING_GUIDE.md，
再读 docs/superpowers/specs/2026-10-06-next-versions.md 与
docs/superpowers/plans/2026-10-06-v2.10-reliability.md。

请检出交付分支 codex/parallel-audit，先核对 git status。
不能 reset、clean、覆盖已有修改、自动提交/推送，不能改 commit.cmd。
不要把远程默认main当成2.9基线；以交付分支、工作区和已保存验收记录为准。
我的额度有限，默认单 Agent，不调用付费模型，不无意义联网，不启动所有后续版本。

先用简短文字说明你理解的当前能力和本次范围，记录 git 状态并执行基线验证。
然后实施 2.10 的任务 1；用失败用例推动实现，完成针对性回归。
如果发现计划与代码有出入，先做只读核实并在 WORK_LOG.md 记录合理的小调整；
涉及产品范围扩大、降低安全/证据门槛或新增运行时依赖时先说明，不要擅自实施。
完成后报告改动、测试、限制和下一任务，并更新 docs/handoff/WORK_LOG.md。
不要只给我建议，要完成本次指定任务的实现和验证。
```

## 继续同一版本

```text
继续 Dual-Agent Studio 的开发。先读 docs/handoff/WORK_LOG.md 和当前版本计划。
检查文件是否仍与记录一致，不要重复完成已有任务。
本次只做计划中下一个未完成任务，保持现有约束和工作区修改。
真实模型联调未授权，使用隔离数据和 Mock/注入响应验证流程。
完成后更新复选框和 WORK_LOG.md，记录真实执行的测试及尚未验证的内容。
```

## 换版本

```text
上一版本已验收，开始执行我指定的下一版本计划。
先核对它的前置依赖是否已实现，并以当前代码更新计划中的文件位置和接口细节。
不要重新实现旧功能；不要把计划草案写成已实现能力。
每次只做一个可独立验证的任务。遇到额度不足时保存完整进度再停，不隐瞒失败。
```

具体版本计划文件名见交接首页。若想提前做 2.11 的预算功能，先确认 2.10 的迁移与运行租约接口已经完成；不能绕过并发保护。

## 独立审核提示词（可在另一个模型里使用）

```text
请只读审核当前指定版本的实现，不编辑文件、不调用真实模型、不创建子 Agent。
先读该版本计划、docs/handoff/ENGINEERING_GUIDE.md 和 WORK_LOG.md。
先核对工作区是否包含更早的未提交修改，只审核 WORK_LOG.md 标明的本版本范围。
重点检查：错误成功判定、证据过期、人工版本绑定、并发/取消/重启、旧数据兼容、
重复请求、路径边界和 UI 与服务端校验是否一致。
发现问题请给出严重程度、具体文件、触发步骤、影响、最小失败用例和修复方向。
不要给无依据的重构建议，不要仅凭测试通过宣称逻辑正确。
无问题时说明审核范围与未覆盖内容，不声称工程绝对没有 Bug。
```

## 每次离开前保存的进度格式

接手模型创建/更新 `docs/handoff/WORK_LOG.md`，旧条目追加保留：

```markdown
## 日期 / 版本 / 任务
- 本次目标：具体用户授权范围。
- 基线：分支、HEAD、已有修改摘要、开始时测试状态。
- 已完成：任务编号、实际行为、关键文件及新接口。
- 决策：为何偏离原草案；未改变的关键约束。
- 数据：schema 是否变化、迁移和回退方式。
- 验证：每条命令、退出码、计数、日志/截图路径；明确 Mock 或真实调用。
- 未完成：具体错误、复现步骤、下一步应改哪处。
- 运行状态：自己启动的进程/端口/临时目录，哪些已关闭。
- 下一步：唯一明确的下一任务及其输入/预期输出。
```

不能填“差不多完成”“应该通过”。若上下文或额度将耗尽，优先写清失败状态和未验证点，避免下一个模型从头猜测。
