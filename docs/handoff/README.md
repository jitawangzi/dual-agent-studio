# 后续开发交接入口

交接基线：2026-10-06，工作区版本 **2.9.0**。本交接包只新增文档；下列 2.10–2.14 均为待实现计划。

## 给项目使用者

把整个当前工程目录交给下一个模型，然后复制 [接手提示词](MODEL_PROMPTS.md) 中的“首次接手”。不必一次执行所有版本，先完成 2.10 并验收，再逐版推进。额度有限时，每次只执行一个任务，按模板保存进度后换模型。

**远程接手请检出 `codex/parallel-audit` 分支。** 交接包编写后，用户授权把2.9实现、测试和文档统一纳入版本提交；默认 `main` 还有独立更新，不能假定它包含本次交付。`.studio` 被忽略，运行记录和本地验收脚本不会随普通 Git 提交转移。是否另行分享运行数据由你决定，其中可能包含工程源码片段、路径和提示词。未来若有本地未提交修改，交接时也需一并核对。

## 接手阅读顺序

1. [当前实现与已知边界](CURRENT_STATE.md)：已做什么、证据在哪里、哪些事情不能假定完成。
2. [工程约束与验证手册](ENGINEERING_GUIDE.md)：运行、测试、浏览器验收、兼容性和交付要求。
3. [五个版本的总体设计](../superpowers/specs/2026-10-06-next-versions.md)：依赖、优先级与明确不做的范围。
4. 只读取本次要执行的版本计划和它引用的文件。

| 推荐顺序 | 版本 | 解决的问题 | 执行计划 |
|---|---|---|---|
| 1 | 2.10 | 数据兼容、残留任务、测试可复现、长期可靠运行 | [稳定性与恢复](../superpowers/plans/2026-10-06-v2.10-reliability.md) |
| 2 | 2.11 | 调用过多、额度耗尽、失败后重复浪费 | [调用预算与资源使用](../superpowers/plans/2026-10-06-v2.11-budget.md) |
| 3 | 2.12 | 小改动也要重复阅读大量无关代码 | [变更分析与定向复查](../superpowers/plans/2026-10-06-v2.12-targeted-review.md) |
| 4 | 2.13 | 模型结论冲突、业务问题卡住闭环 | [争议处理与人工决策](../superpowers/plans/2026-10-06-v2.13-decisions.md) |
| 5 | 2.14 | 审核证据难带走、历史数据增长、迁机困难 | [证据导出与存储维护](../superpowers/plans/2026-10-06-v2.14-portability.md) |

2.11 最能直接降低后续运行浪费，但建议先完成 2.10 的迁移和生命周期保护。每个版本应独立可用，不以“等后续版本完成才可运行”为交付结果。

## 交接清单

- [ ] 保存当前完整工作区，确认包含未跟踪的 `engine/`、`public/`、`tests/` 和 `docs/` 新文件。
- [ ] 新模型读取本目录文档及根目录 `AGENTS.md`，承认后者的旧架构说明不覆盖全部 2.x 实现。
- [ ] 记录 `git status --short`，不得清理、重置或自动提交已有修改；不要改动 `commit.cmd`。
- [ ] 在隔离数据目录执行基线测试；记录当前环境和失败信息，先区分旧问题与新回归。
- [ ] 每次仅执行一个指定任务；默认单 Agent，真实模型联调和扩大范围需要用户明确安排。
- [ ] 按 [提示词文档](MODEL_PROMPTS.md) 中的模板记录进度、验证和下一步，便于换模型继续。

交接规划本身没有执行后续版本开发。随后用户授权提交远程，提交前重新执行了全量测试；具体记录见 WORK_LOG.md。
